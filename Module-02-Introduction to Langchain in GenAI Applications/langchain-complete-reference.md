## What is LangChain?

LangChain is an **open-source framework** for building applications powered by Large Language Models (LLMs). Rather than just calling an LLM directly, LangChain lets you connect prompts, models, memory, and external data sources into structured, reusable pipelines.

**Why LangChain over raw LLM calls?**

| Need | LangChain Solution |
|---|---|
| Multi-step processing | Chains |
| Context across turns | Memory |
| External data integration | Agents + Tools |
| Structured, reusable workflows | LCEL Pipelines |

**Common use cases:** Question-answering systems · Document summarization · Data extraction · AI-powered assistants

---

## Core Components

### 1. Language Model

A language model takes **text input and generates text output**. It is the foundational building block for task completion and document summarization.

Supported providers: IBM · OpenAI · Google · Meta

---

### 2. Chat Model

A chat model is built on top of a language model but is optimized for **conversational interactions** — it responds in a human-like, back-and-forth manner.

**Chat Message Types:**

| Type | Purpose |
|---|---|
| `HumanMessage` | Input from the user |
| `AIMessage` | Response generated by the model |
| `SystemMessage` | Instructions that guide the model's behavior |
| `FunctionMessage` | Handles outcomes from function calls |
| `ToolMessage` | Manages interactions with tools |

> Every message has two properties: **role** (who is speaking) and **content** (what is said).

---

### 3. Prompt Templates

Prompt templates translate user inputs into **clear, structured instructions** for the model.

**Types of Prompt Templates:**

| Template Type | Description |
|---|---|
| **String Prompt Template** | Simple single-string formatting |
| **Chat Prompt Template** | List of messages with role and content |
| **Message Prompt Templates** | AI, System, Human, and Chat variants |
| **Messages Placeholder** | Full control over message rendering |
| **Few-Shot Prompt Template** | Provides examples to guide the LLM's behavior |

**Example Selectors** (used with Few-Shot templates):

- **Semantic Similarity** — selects examples most similar to the input
- **Max Marginal Relevance** — balances relevance with diversity
- **N-Gram Overlap** — selects based on textual similarity

---

### 4. Output Parsers

Output parsers transform **raw LLM text output** into structured, usable formats for downstream processing.

**Supported output formats:** `JSON` · `XML` · `CSV` · `Pandas DataFrames`

> Example: A *Comma Separated List Output Parser* converts the model's response into CSV format, ready for spreadsheet analysis.

## Chains

A **chain** is a sequence of calls where the **output of one step becomes the input for the next**, forming a seamless information pipeline.

### Sequential Chains

In a sequential chain:
- Each step takes **one input** and produces **one output**
- Steps are executed in order: Step N output → Step N+1 input
- All steps are wrapped into a **single unified pipeline**

```
[User Prompt] → Chain 1 → Chain 2 → Chain 3 → [Final Output]
```

---

### 3-Chain Example Walkthrough

**Goal:** Given a location, find the famous dish → get its recipe → estimate the cooking time.

```
Location (China) → Peking Duck → Recipe → Cooking Time
```

#### Chain 1 — Location to Dish

**Input:** `location` → **Output:** `meal`

```python
template = "What is a famous dish from {location}?"
prompt = PromptTemplate(input_variables=["location"], template=template)

location_chain = LLMChain(llm=mixtral_llm, prompt=prompt, output_key="meal")
```

#### Chain 2 — Dish to Recipe

**Input:** `meal` → **Output:** `recipe`

```python
template = "Give me a simple recipe for {meal}."
prompt = PromptTemplate(input_variables=["meal"], template=template)

dish_chain = LLMChain(llm=mixtral_llm, prompt=prompt, output_key="recipe")
```

#### Chain 3 — Recipe to Cooking Time

**Input:** `recipe` → **Output:** `time`

```python
template = "Estimate the cooking time for this recipe: {recipe}"
prompt = PromptTemplate(input_variables=["recipe"], template=template)

recipe_chain = LLMChain(llm=mixtral_llm, prompt=prompt, output_key="time")
```

---

### Combining into a SequentialChain

```python
from langchain.chains import SequentialChain

overall_chain = SequentialChain(
    chains=[location_chain, dish_chain, recipe_chain],
    input_variables=["location"],
    output_variables=["meal", "recipe", "time"],
    verbose=True  # traces the full information flow step by step
)

result = overall_chain.invoke({"location": "China"})
```

> Setting `verbose=True` shows exactly how each input is transformed at every step through to the final output — useful for debugging.

## Memory

Memory allows chains and agents to **read and write historical data**, preserving context across multiple interactions.

**Memory lifecycle in every chain:**

```
Before execution → Memory READ  → enhances the user's input with past context
After execution  → Memory WRITE → current inputs & outputs saved back to memory
```

**`ChatMessageHistory`** is the built-in class for managing conversation history:

```python
from langchain.memory import ChatMessageHistory

history = ChatMessageHistory()

history.add_ai_message("Hi!")
history.add_user_message("What is the capital of France?")

# Memory now contains:
# [AIMessage: "Hi!", HumanMessage: "What is the capital of France?"]
```

All stored messages are injected as context for subsequent model calls, enabling coherent **multi-turn conversations**.

## Agents

Agents are **dynamic systems** where an LLM autonomously decides what actions to take and in what sequence — going far beyond the fixed steps of a static chain.

**How agents work:**

| Aspect | Detail |
|---|---|
| **Decision-making** | The LLM reasons about which action to take next |
| **Execution** | Does not act directly — delegates to external tools |
| **Tools** | Search engines, databases, APIs, websites, etc. |

**Example flow — "What is the population of Italy?"**

```
User Query
    ↓
Agent (LLM selects the right action)
    ↓
Queries external database / tool
    ↓
Returns curated, accurate answer
```

**Pandas DataFrame Agent** — a specialized agent for querying tabular data with natural language:

```python
from langchain.agents import create_pandas_dataframe_agent

agent = create_pandas_dataframe_agent(
    llm=chat_model,
    df=dataframe,
    verbose=True
)

response = agent.invoke("How many rows are in the dataframe?")
# Output: "There are 139 rows in the DataFrame."
```

Under the hood, the LLM translates the natural language query into Python code, executes it against the DataFrame, and returns a precise answer.

## LCEL — The Modern Chaining Method

**LangChain Expression Language (LCEL)** is the modern, recommended way to build LangChain pipelines. It uses the **pipe operator `|`** to connect components into clean, readable workflows.

```
Input | Component 1 | Component 2 | Component 3 | Output
```

### Why LCEL over LLMChain?

| Feature | Traditional LLMChain | LCEL |
|---|---|---|
| Readability | Moderate | High — pipe syntax is intuitive |
| Composability | Limited | Excellent |
| Parallel execution | Manual | Built-in via `RunnableParallel` |
| Async support | Limited | Native |
| Streaming | Complex | Simplified |
| Automatic tracing | No | Yes |

---

### Core Steps

Every LCEL chain follows four steps:

1. **Define a template** with `{variable}` placeholders
2. **Create a `PromptTemplate`** instance
3. **Build the chain** by connecting components with `|`
4. **Invoke** with input values

```python
template = "Tell me a {adjective} joke about {content}."
prompt = PromptTemplate(input_variables=["adjective", "content"], template=template)

chain = prompt | llm | StrOutputParser()

response = chain.invoke({"adjective": "funny", "content": "cats"})
```

---

### Runnable Primitives

Runnables are the **interfaces and building blocks** that LCEL uses to connect components.

#### RunnableSequence
Chains components **one after another** — output of each feeds into the next.

```python
# Explicit
chain = RunnableSequence(first=component_1, last=component_2)

# Preferred LCEL shorthand
chain = component_1 | component_2
```

#### RunnableParallel
Runs **multiple components simultaneously** on the same input.

```python
parallel_chain = {
    "summary":     summary_chain,
    "translation": translation_chain,
    "sentiment":   sentiment_chain
}
# Output: {"summary": "...", "translation": "...", "sentiment": "..."}
```

#### RunnableLambda
Wraps a **regular Python function** into a runnable pipeline component.

```python
from langchain_core.runnables import RunnableLambda

def format_prompt(inputs):
    return f"Tell me a {inputs['adjective']} joke about {inputs['content']}."

chain = RunnableLambda(format_prompt) | llm | StrOutputParser()
```

---

### Type Coercion

LCEL **automatically converts** Python objects into compatible Runnable types — no manual wrapping needed.

| Python Type | Auto-converted To | Behavior |
|---|---|---|
| `dict` | `RunnableParallel` | Runs all values concurrently on the same input |
| `function` | `RunnableLambda` | Transforms inputs using the function |

### LCEL Examples

#### Simple Sequential Chain

```python
joke_chain = (
    RunnableLambda(format_prompt)  # formats the prompt
    | llm                          # generates a response
    | StrOutputParser()            # parses to plain string
)

result = joke_chain.invoke({"adjective": "funny", "content": "programmers"})
```

**Data flow:**
```
{"adjective": "funny", "content": "programmers"}
    ↓ RunnableLambda → "Tell me a funny joke about programmers."
    ↓ LLM            → "Why do programmers prefer dark mode? Light attracts bugs!"
    ↓ StrOutputParser → final plain string
```

#### Parallel Chain

```python
parallel_chain = {
    "summary":     PromptTemplate.from_template("Summarize: {text}")     | llm | StrOutputParser(),
    "translation": PromptTemplate.from_template("Translate to French: {text}") | llm | StrOutputParser(),
    "sentiment":   PromptTemplate.from_template("Sentiment of: {text}")  | llm | StrOutputParser()
}

result = parallel_chain.invoke({"text": "LangChain makes AI development easy and fun!"})
# { "summary": "...", "translation": "...", "sentiment": "Positive" }
```

---

### LCEL vs LangGraph

| Use Case | Recommended Tool |
|---|---|
| Simple sequential pipelines | ✅ LCEL |
| Parallel task execution | ✅ LCEL |
| Prompt + LLM + parser flows | ✅ LCEL |
| Complex workflows with branching logic | ✅ LangGraph |
| Stateful or cyclical agent workflows | ✅ LangGraph |

> Best practice: Use **LCEL within nodes** and **LangGraph between nodes** for complex applications.

## LangChain Data Flow

```
User Input
    ↓
Prompt Template     (structures the input)
    ↓
LLM / Chat Model    (generates a response)
    ↓
Output Parser       (structures the output)
    ↓
Final Structured Output
```

Memory reads before each step and writes after — agents can branch this flow by calling external tools at any point.
